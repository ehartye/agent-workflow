# Criterion QA and bounded captured research

Use `plugin:criterion-review` to review fixed criteria and `plugin:evidence-research` to inspect frozen sources/questions. These are separate QuickJS scripts, with literal exported metadata and top-level JSON returns. Never import them into Node or execute them in the host. `parallel` takes zero-argument functions. Validate the exact installed definition through the public CLI before an authorized start.

Record the input decision as a snapshotted `--args-file` (supported since 0.3.6) with small literal descriptors. Each file descriptor is `{path,sha256,bytes}`; the coordinator freezes actual bytes inside the authorized read scope. A path inside saved args does not freeze external bytes. Workers verify full-file regular/link/ancestor safety, SHA-256 and byte count before and after reading. The guest has no filesystem and cannot authenticate those claims. Cached replay is not fresh evidence. Bulk text belongs in frozen files; large inputs use reviewed range descriptors. Never print source manifests or transcripts.

Both roots require `version:1`, `roleSelections` and `limits`. Every role has exactly `{skills:[declared IDs],requireTools:[declared IDs]}`; explicit none is `{skills:[],requireTools:[]}`. Criterion roles are `reviewer`, `skeptic`, `reducer`; research roles are `reader`, `skeptic`, `reducer`. The scripts forward those exact arrays to agent options with read-only/no-network/never permissions, one attempt and no worker wall deadline. A selected skill grants no additional authority. Unknown root/nested fields are rejected. Model, environment, permissions and arbitrary settings in role JSON are unsupported.

Criterion root: `{version,criteria,artifactInventory,roleSelections,limits}`. Criteria are `{id,text,evidenceRefs}`; evidence refs are exact inventory descriptors. There are 1–32 unique IDs, 1–4 refs per criterion, up to128 artifacts, text<=1000 characters. Limits are `{maxCriteria,maxStarts,maxRounds}` with maxCriteria1–32, maxRounds1–2 and maxStarts1–128. Preflight refuses `2*criteria.length*maxRounds+1 > maxStarts`. Each configured round has a reviewer followed by a separate independent skeptic per criterion. Even a null review reaches a new skeptic with actual evidence descriptors. Later rounds are explicitly planned independent inspection; they never erase earlier nulls. One final reducer receives compact coverage, not authority to rewrite reports.

Research root: `{version,sources,questions,roleSelections,limits}`. Source `{id,path,sha256,bytes,modality}` uses modality `text|image|document`. Questions are `{id,text}`, up to32 unique IDs with text<=500 characters; sources1–64. Optional source `selection:{disposition:'sampled'|'dropped',reason}` explicitly excludes that descriptor before dispatch. Optional `range:{start,end}` is a half-open byte range within the full file; full-file identity is still verified and coverage stays partial. Limits are `{maxSources,maxStarts,maxRounds,dryRoundLimit}` with maxima64/256/2/2 and all minima1. Preflight computes `2*sources.length*maxRounds+maxRounds`, including skeptics/reducer in every round, even for excluded sources. An overbudget plan returns `stopReason:'startBudget'` without dispatch. Never append sources or hide exclusions to fit.

Each research round reads explicit pending sources once, runs separate skeptics with original evidence and read claims, then a bounded reducer. Only a verified partial read explicitly requesting continuation, with verified skeptic evidence and skeptic disposition `read` or `partial`, can enter the next planned round. Lost/failed/inaccessible readers or skeptics are not automatically retried. A round with no new supported question increases dryRounds. Stop reasons are `inventoryExhausted`, `dryRounds`, `roundLimit`, `startBudget`, `blocked`. Exhausted means the fixed pending list ended, not that all questions or all possible evidence were covered.

IDs are unique portable strings<=80 characters, including data IDs such as `__proto__`; selection IDs<=16 per array. Literal file paths<=200 characters, lowercase SHA-256 and safe byte counts0–512MiB are required. Use smaller reviewed descriptors for longer or larger material; never silently truncate. Reports are intentionally small: each evidence observation names path/hash/bytes plus `verified|missing|changed|inaccessible`. Criterion reports include criterionId/verdict/evidenceRefs/dissent. Research readers include sourceId/disposition/evidenceRefs/answers/limitations/dissent/needsNextRound; skeptics include sourceId/disposition/evidenceRefs/verdict/questionIds/limitations/dissent. Detailed evidence stays in captured source artifacts; these reports carry bounded claims, not full transcripts.

Criterion rows retain every `{review,skeptic}` slot and `reportedPass|reportedFail|unverified`, actual evidence refs and dissent. A pass requires matching positive observations from both roles in every configured round. Covered IDs mean inspection coverage, including reported failures, not accepted criteria. Missing/unread/changed/null evidence remains unverified. Research rows retain all original source IDs, original reports and exactly one final `read|partial|inaccessible|failed|sampled|dropped` disposition. `expected === accounted === sum(counts)`. `allSeenIds` includes attempted sources only. Question coverage requires independent, consistent support; dissent is never replaced by reducer prose.

An earlier verified partial round can have no answer yet; a later planned round may establish it. Each retained reader/skeptic slot in that source's history must have matching verified identity and an eligible disposition. Every round that claims the question's answer must independently support it in that same round. A later null slot or unsupported answer claim cannot inherit an earlier positive. Original reports and dissent remain retained.

Every result has `complete:false,completionAuthority:'coordinator'`. Missing roles, questions and source/criterion coverage stay explicit. A verified skeptical contradiction in any source leaves that question in `disputedQuestionIds` and missing, even when another source supports it. A reducer receives `summaryScope:'reportedCoverageOnly'` and compact coverage metadata, including dissent counts and research question disputes. Its role-specific instructions require selected-skill activation but assign no source artifacts or file inspection. It summarizes reported coverage; it does not synthesize source contents, independently certify source claims or replace the full original reports, answers, limitations and dissent retained in result rows. A substantive evidence synthesis needs a separately reviewed bounded handoff. A reducer can return only a bounded summary/dissent; it cannot manufacture delivery, receipts or a missing skeptic. Worker refs are resolved externally from saved producer records, never guessed from guest indexes.

Per-report serialized UTF-8 budgets are4096 bytes for criterion roles and1536 for research roles, below the engine/schema limits. Each prompt declares `reportLimitBytes`. An oversize response becomes a null slot with an `oversizeReports` entry containing worker ID, role, observed bytes and limit. It is not truncated, accepted or retried; inspect the original saved worker result separately. These bounds keep maximum admitted round/inventory results within the guest broker envelope while preserving missing coverage. Use owned full artifacts for material that cannot fit a bounded report.

Before launch, identify actual admitted retained roots and tools per role. Genuine executor list/read must use returned identities and native pagination. A failed native reference read remains failed. Out-of-package references need separately admitted path/hash and ordinary read after activation; never shell-load SKILL.md as invocation. Required tool readiness and actual modality operations are separate evidence. Unavailable modality means inaccessible. Source support and controlled evaluator fixtures do not establish native research efficacy or a new paired skill benefit.

The coordinator reviews exact producer/run/generation/position/cumulative attempt, positive owned cleanup, original outcomes/effects, complete captures and artifact identities. Dependencies do not transfer files. Integrate reviewed bytes into a stable combined checkout, obtain fresh checks there and independently accept each objective. Where an approved single-run pipeline uses an external barrier, bind fresh verifiers to its independently frozen F/V identities and literal admitted checks; the original worker checkout is not integrated source. Keep live gates, receipts and observer cursors outside frozen source. The approval report remains separate from unchanged recipe output.

For package/catalog loss, preserve failed slots, source checks, possible outputs, original effects and independent completed writers. Reconcile effects and verify current retained sources before a fresh admitted continuation for eligible unfinished work. Never rewrite saved bindings or retry after a lost mutating response. Positive job cleanup covers owned process drain, not global external-effect reconciliation. A missing build tool blocks its checks while independent source work continues. Return exact command/executable/cache evidence. Complete the path through reviewed capture, integration, fresh checks and coordinator acceptance; historical unknown evidence remains unchanged.
