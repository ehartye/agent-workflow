description: Install, repair or check the owned Agent Workflow runtime when the user asks to set up the plugin, the CLI reports a missing managed runtime, or a plugin update requires setup.
---

Use the packaged CLI without a custom MCP server. Resolve plugin-root from this installed skill: two parents above its directory. Require Node 24+ and npm. Setup copies a fingerprinted runtime outside mutable plugin cache, installs locked production dependencies with lifecycle scripts disabled, and selects it for new runs. Existing authorization to install/update covers these steps; do not ask again.

Packaged `resources/` copies are for native instruction/reference reads. Execute CLI and recipes from the real plugin-root resolved above, never a generated resource copy. Activate cross-skill roles through genuine executor `skills.list` and `skills.read` using returned package/main_resource; resource availability grants no installation or other permissions.

For the working-tree candidate above released 0.5.0, use [upgrade boundaries](resources/skills/workflow-setup/references/upgrades.md) before relying on declared steps, depth-one composition or LAN binding in a saved run. Follow [LAN launch/Close](resources/docs/dashboard-lan.md) for exact interface admission and manual lifecycle; setup/doctor does not establish second-device or phone painted acceptance. [Resource/source limits](resources/docs/api.md#worker-capability-bundle) distinguish generated same-package references, native activation and bounded stdin readiness from installed tool operations.

The shared CLI/hook data directory is explicit --data-dir, otherwise AGENT_WORKFLOW_DATA_DIR if set, then LOCALAPPDATA/agent-workflow (home .local/share/agent-workflow without LOCALAPPDATA). PLUGIN_DATA does not implicitly select another instance. Keep explicit data selection identical across setup, doctor, runs and mode; never store managed state in plugin cache.

```text
node "<plugin-root>/bin/launch.mjs" setup
node "<plugin-root>/bin/launch.mjs" doctor --cwd "<project>"
node "<plugin-root>/bin/launch.mjs" workflows --cwd "<project>"
```

Add --data-dir "<directory>" to each command when explicitly selected. In PowerShell keep executable/arguments separate and use the call operator for a quoted executable path. JSON escaping is not shell quoting.

Setup accepts no `--cwd`; doctor and workflows do. In non-login PowerShell use the verified `node.exe` and `npm.cmd`, never an implicit `npm.ps1`. Native `yield_time_ms` observes a running process; it does not set its execution deadline. For Windows ESM imports use `pathToFileURL(absolutePath).href`, not a raw drive-letter module specifier. Inspect effects before considering another command after an uncertain result.

Use coordinator-verified absolute Node/`npm.cmd`/PowerShell paths, bounded command time/output and profile loading disabled (`-NoProfile`) where supported. Use explicit UTF-8 decoding for bounded report reads. Follow [worker prerequisites](resources/skills/agent-workflow/references/worker-prerequisites.md) to distinguish discovery, command admission, installed browsers and sandbox render transport; one passing stage does not establish another.

Read [upgrades](resources/skills/workflow-setup/references/upgrades.md) before updating/repairing existing state. Preserve old runtime versions/run data and active work. A missing/changed package requires explicit setup, never installation during dispatch.

For worker skill/tool preparation, read [worker capabilities](resources/docs/worker-capabilities.md). New runs default to parent authority and enabled native catalog provisioning, using the coordinator's actual originating-session context; choose `--access restricted` deliberately. See the authoring skill's admission/replay reference through its genuine native package for the exact snapshot. The coordinator prepares explicitly authorized toolchains and any required immutable role bundle of declared skill/tool IDs. Preserve absolute original skill sources and their plugin-relative references/assets; verify exact Node/cache-launcher invocation, installed runtime/source/dependency receipts and named managed-home/browser cache values. Runtime setup or enabling a parent plugin does not establish deliberate role selection, worker native list/read invocation, associated CLI readiness or artifact production.

Parent writers' separate worktrees organize edits and captures; full parent access does not create an OS filesystem boundary. Restricted MXC admission is a separate selected policy. Check readiness inside the actual assigned workspace/policy. Missing build/render prerequisites block those checks while useful authorized source work continues. Local offline dependency installation requires explicit workspace authorization; never copy parent dependencies, make junctions or install as a fallback.

Report native selected-skill activation, CLI/runtime readiness and dependency/cache readiness separately. A genuine main read proves invocation at its admitted root; it does not establish an installed CLI, browser cache or completed tool operation. Conversely, a passing setup/doctor cannot replace the role's genuine native main read. Before producer dispatch/freeze, review the exact provider types/envelopes, complete source/dependency inventories and declared fixture roots with their owners; a missing provider leaves dependent checks unrun until reviewed integration. Use the authoring skill's directly linked admission/replay procedure for that review.

Confirm returned `skill_root` and use native resource/cursor pagination. Source retention does not preserve external managed homes, services, dependencies or host connections. Missing/corrupt retained storage and changed backend/configuration fail closed. Host extraRoots does not expose these tools. Resume/restart retain the saved bundle/runtime identity. Only passed required tools supply exact verified Node/launcher/environment/readiness metadata to the initial task. Readiness and task execution share the worker deadline after startup. Native out-of-package documentation may be read ordinarily only at explicitly declared, hash-verified paths after genuine activation; this cannot replace skill invocation. Do not automatically install, swap versions, widen permissions, change global policy or retry uncertain mutating effects. Setup/cache presence and capability/version output cannot prove render transport or artifact generation.

The updater transaction belongs to the host integration; its locking cause may remain unknown.
