# Worker prerequisites

The coordinator owns toolchain preparation. Workers inherit isolated worktrees and restricted launch environments, not the parent session's installed dependencies or verified host execution context. Discover and check the required executable, package cache and renderer before assigning dependent validation. Do not silently install prerequisites, change PowerShell execution policy, or expand filesystem/network permissions to make a command work.

On Windows, an `npm` command may resolve to an execution-policy-blocked `npm.ps1`. Supply the verified `npm.cmd` executable when needed. MXC also redirects `LOCALAPPDATA`, which can move implicit npm and Playwright cache lookups. For an authorized offline dependency installation, the coordinator can supply `npm.cmd ci --offline --cache "<verified absolute npm cache>"`. An offline cache miss is a blocker to that installation, not permission to download packages or repeat uncertain writes. Package installation can execute lifecycle scripts; the coordinator must explicitly authorize the installation and decide whether scripts are required. Prefer having workers author code/recipes and running the dependent build or renderer separately when the prerequisite cannot be supplied safely.

Before authorizing installation/build inside a writer worktree, account for artifact capture: by default all untracked outputs are included even when ignored, including `node_modules` and `dist`. The current limits are 20,000 files, 128 MiB captured bytes and 32 MiB per diff. A successful installation can therefore prevent final diff capture. Prefer coordinator-side dependency installation/build when it would exceed these limits. Alternatively a new run may receive an explicit coordinator-owned [immutable capture policy](../../../docs/session-delivery.md#explicit-writer-capture-policy) before dispatch, protecting every assigned output and retaining an excluded metadata inventory. Worker-edited ignores never set capture authority. Capture failure preserves the workspace and unknown status; inspect `workspaceError.capture` for its stage and sanitized cause. Do not delete evidence, retroactively change policy or replay an unknown writer to obtain a cleaner result.

For preinstalled Playwright browsers, the coordinator may explicitly set `PLAYWRIGHT_BROWSERS_PATH` to the absolute cache directory before workflow launch. Workflow forwards only this named toolchain path and includes it in backend identity. Keep it consistent on resume and dashboard launch. Executable discovery does not prove a browser can render inside MXC. No automatic browser installation or sandbox weakening is authorized by this setting.

After a startup or preflight failure, report the blocked command, relevant executable/cache path and observed evidence. Pause dependent work and continue independent authorized authoring or review within the assigned files. A process that ran and exited nonzero is not `notStarted`; it may already have changed files. Unknown or potentially mutating effects require coordinator reconciliation before retry/fallback. Report unrun checks and incomplete assets explicitly in the final result.
