For multi-worker deliverables, read [workflow authoring](../workflow-authoring/SKILL.md) to define scope/ownership, pass scout JSON into actual writers, review retained artifact handoffs, and require coordinator integration plus fresh verification. For workers needing skills and associated tools, read [worker capabilities](../../docs/worker-capabilities.md) and [worker prerequisites](references/worker-prerequisites.md). Select declared IDs from the immutable new-run bundle. Exact native `selectedCapabilityRoots` bindings expose executor `skills.list`/`skills.read`; workers use returned packages without invented aliases or copied skill bodies. Native invocation, required CLI readiness and artifact acceptance are separate. Passed required tools supply exact verified executable/environment metadata; admitted workers perform authorized operations. Missing prerequisites block only dependent work. [Native acceptance](../../docs/verification.md) covers skill invocation and nonrendering Beeps authoring, not WAV/listening or sprite export.

For explicit capture exclusions, bounded inventory inspection, reversible visibility and reviewed retirement, use the [session delivery contracts](../../docs/session-delivery.md). Freeze any policy before launch and protect all assigned output paths. Existing unknown captures cannot be recollected by changing policy.

2. Write literal exported metadata first, then top-level async work and return. Run `validate "<script-file>"`. Save with `save "project:name" --script "<script-file>" --cwd "<project>"`; add `--command` for a requested reusable named skill and `--overwrite` only for authorized replacement.
3. Start with `run "<scope:name>" --cwd "<project>" --session "<originating-session>" --args '<JSON>'`, or replace the name with `--script "<script-file>"`. Use the real Codex session from context or CODEX_THREAD_ID; never invent one. Default to read-only. Add `--writable` only for authorized edits; each writer uses a separate Windows MXC worktree. Capability-enabled new runs accept `--worker-capabilities <JSON manifest file>`; use the exact public schema. Resume/restart retain the original bundle. Review patches before authorized integration; no automatic merge.
4. Capture the exact returned run ID and generation. Immediately attach a named live observer using the returned `watch.argv` argument array. The receipt says `attached:false`; only a consumed JSONL `attached` record proves the observer has connected. Inspect `status "<run-id>"` and `result "<run-id>"`. Call `dashboard "<run-id>" --session "<originating-session>"` and return the complete authenticated URL to the owner, including its fragment. Keep the token out of shared reports. A startup receipt or successful status command does not establish completion.
5. Keep the observer attached until the run-terminal event. Report worker failure/unknown, idle warning and terminal events promptly to the originating coordinator; do not wait for the user to notice the dashboard. Report failed/unknown workers, null verifier slots and missing item IDs explicitly. Synthesis cannot fill missing evidence. Inspect controls and errors before replay or restart; never retry an uncertain dispatch merely because the CLI failed.

## Live observation after every detached start

Use `watch "<run-id>" --session "<originating-session>" --generation N --after 0 --jsonl` with the same explicit data directory. This read-only command uses the run's recorded runtime and exits on its durable run-terminal event. `--poll-ms` is 100–10,000 (default 500); `--idle-ms` is 1,000–86,400,000 (default 60,000). Idle warnings mean no newly observed completed command/file-change activity for a running worker. Commentary does not reset the clock; a warning is not proof of deadlock or permission to restart.

Name an attached coordinator or collaboration observer for each detached run, resume and restart. Give it the exact watch argument array, run/generation, and originating coordinator identity. It consumes JSONL continuously, saves the last processed durable event `seq`, and promptly sends worker failures/unknown outcomes, idle warnings and run terminal to that coordinator through the available collaboration channel. A spawned observer without a consumed `attached` record is not confirmed. The CLI does not push into the host chat or modify a parent thread; the attached observer supplies that bridge. If no collaboration observer is available, the coordinator must keep the watch attached itself.

After a dropped consumer, reconcile saved status and reconnect with `--after` set to the last event the consumer actually processed. Retain the same session and exact generation; a new generation requires fresh attachment. Do not advance a cursor from unprocessed output. Watcher exit, EPIPE, or an idle warning never stops, retries or cancels workers. An observation error means monitoring coverage is missing; report it and inspect the retained run. Older retained runtimes may not support watch. Inspect their existing status/result explicitly and disclose the missing live surface instead of silently migrating them.

All commands accept --data-dir for explicitly selected state; keep it consistent. Otherwise use AGENT_WORKFLOW_DATA_DIR if set, then LOCALAPPDATA/agent-workflow (home .local/share/agent-workflow if LOCALAPPDATA is absent). PLUGIN_DATA does not implicitly select another instance. If installation is missing or changed, use workflow-setup.

Runs normally continue until script completion or manual Stop, and the dashboard stays available until explicitly closed. Do not infer that the host session ending stops either process. Workers have a 10-minute default deadline; `run`/`resume --worker-timeout-ms` can select 1–1,800,000 ms. For a deliberate overall wall limit use `--run-timeout-ms` (1–86,400,000; 0 removes it). Resume inherits saved limits unless overridden. CPU/memory limits and a no-broker-work idle watchdog remain enforced.

Workers use pinned native Codex App Server with existing managed ChatGPT login. There is no API-key fallback, custom MCP server, parent history/tool-grant inheritance, native composer switch or shared parent token budget. Observed usage is evidence, not a hard spending cap. Workflow mode grants no permissions. SSH verification remains deferred.
