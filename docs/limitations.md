# Boundaries and limitations

Agent Workflow implements the approved regular-plugin boundary. These differences are part of the product contract.

| Area | Supported behavior and boundary |
| --- | --- |
| Host UI | Owned authenticated loopback dashboard. No documented native composer highlighting, effort slider, or stock task-panel insertion is claimed. |
| Background work | Owned detached local supervisor and durable JSON records. The machine, permissions, Node runtime and local account must remain available; there is no hosted/cloud execution promise. |
| Budget | Cumulative observed worker output-token scheduling guard. In-flight overshoot, missing backend usage and native parent-token spending remain distinct. No native hard shared pool or provider cache economics equivalence. |
| Permissions/context | Explicit worker cwd/configuration, sandbox/network/approval ceiling, and project instructions. Live parent history, connected-tool grants and session-native roots are not inherited automatically. Read-only filesystem sandboxing does not restrict the effects of configured MCP tool calls. |
| Isolation | Separate QuickJS child with JSON-only broker, bounded CPU/memory and no exposed host APIs. Worker worktree failures reject; no shared writer fallback. QuickJS containment is an implementation boundary, not a claim that arbitrary native processes under the same OS user are isolated. |
| Effects/retries | No transport fallback after uncertain dispatch. Every abandoned dispatched worker remains unknown, including read-only/drained workers, until effects review and verified drain permit explicit reconciliation. Stop and replay do not roll back edits; writer restart is restricted. |
| Quota/stalls | Quota waits require exact structured quota error, no observed effects, exact exhausted-window reset metadata and explicit bounded `quotaWaitMs`; default 0 disables waits. Known tools, compaction, sleep and user approval suspend only the stall watchdog; hard timeout remains active. Safe stall retries are bounded by `stallRestarts` (0–5) and preserve cumulative attempts/spend. |
| Durable evidence | `run.json` is the sole authoritative atomic commit. Missing/stale derived event files are rebuilt; ahead/conflicting files block recovery and are preserved for manual evidence review. |
| Replay | Ordered prefix reuse by call position, previous key, prompt and stable options. Exact runtime source/dependency identity mismatch rejects resume; changed backend/profile fingerprint invalidates prefix. External workspace evidence freshness is not inferred. Completed later siblings lose reuse after a changed/failed prefix. |
| Nested work | One-level named child workflow shares concurrency, attempt limit, cancellation and observed budget. Recursive child workflows reject. Worker recursion guards prevent plugin tools from silently creating independent nested runs. |
| Writer integration | Worktrees retain changes and artifact patches. Recipes return evidence for coordinated integration; automatic merging/publishing is not part of a workflow recipe. |
| Approvals | App-server approvals remain pending until an explicit decision, except an approvalPolicy of never declines. Native host trust for bundled hooks is a separate review. |
| Packaging | Fresh cache copies need explicit managed setup; a dependency-free read-only setup-info MCP keeps exact native host data paths discoverable first. No silent updater or bootstrap workflow dispatch. Native isolated install/onboarding/cold setup-info/warm tools and portable stdio are checked. A repository check alone cannot prove a specific desktop installed cache refreshed. |
| Hooks/distribution | Opt-in UserPromptSubmit routing for genuine user prompts. No global AGENTS mutation. Hook-bearing packages require manual/local host installation/trust and are currently excluded from the public plugin directory. |
| Validation | Literal meta/module/syntax validation happens before dispatch; actual worker JSON is independently validated with the shared bounded schema subset. Regex/dynamic features and `uniqueItems` are unsupported. Runtime host API violations remain isolated execution errors. Failed/null/unverified task slots are preserved instead of being replaced by synthesis. |

The app-server adapter targets a pinned experimental protocol; future Codex protocol changes require an explicit adapter/runtime update and revalidation. Installed runtime versions are immutable so a plugin update cannot silently replace a paused run’s evaluator. Source/workspace changes, manual edits, deleted artifacts, controller death, quotas and external service availability can invalidate reuse or leave incomplete outcomes.

Reliable orphan process-identity inspection is implemented for Windows and Linux. This build was exercised on Windows; Linux `/proc` recovery requires verification on Linux. Darwin currently lacks reliable identity inspection and therefore fails closed with an unverified orphan rather than replaying it. A crash that leaves a stale recovery/controller claim also fails closed; manual cleanup requires first verifying that the prior controller is absent and reviewing the recorded claim and worker effects. Do not blindly delete ownership records to force replay.

Verified drain covers discoverable owned process trees, not every process or external effect a worker might have started. Detached/reparented descendants and remote/MCP effects cannot be proven absent by killing a worker PID. Missing ownership or drain evidence remains `ORPHAN_UNVERIFIED` and requires reviewed recovery rather than a blanket cleanup claim.

Native isolated installation/read checks resolve the exact onboarding SKILL.md and enabled skills. The installed host returned no hook summaries with trust unset; trusted native hook activation has not been verified. Hook definition/path validation and subprocess routing tests do not establish that the host user has completed trust review. Enablement/trust remains an explicit host action; no automatic approval or global host mutation is performed.

Offline fixture tests demonstrate deterministic orchestration and real process/persistence boundaries. Read-only authenticated smoke verifies the actual transport separately. These checks do not establish universal multi-agent quality, cost advantage, provider caching equivalence, or perfect parity with every native Claude/Codex host feature. Paired authoring evaluation must report baseline quality and actual evidence rather than treating a well-formed skill as measured benefit.
