# Workflow monitor

The session monitor presents a selected persisted run in the owner-selected Map + inspector layout. The approximately 44px blue light-mode run bar shows the actual run title and execution status, Messages, Workers, Pause and More. More contains session navigation, the separately armed control target, Stop/Resume, refresh and connection evidence, record management, theme settings, artifacts and Close dashboard. Opening these surfaces does not change execution or remove records. System, Light and Dark remain available with saved preference and keyboard focus returning from theme settings on Escape.

The map occupies the remaining viewport beside a 300px desktop inspector with its own scrolling. The inspector opens initially on recorded evidence, can be closed, and reopens when a worker is selected. The approximately 31px footer opens the full ordered, filtered worker tray. More and Messages are separate drawers over the retained map and inspector. Escape and Close restore the initiating control using its stable identity, including rebuilt map and tray controls.

Below 600px, the map is a locally scrollable 382px world of two columns of 164px HTML cards. Workers continue across phase boundaries. The desktop graph is never scaled down to fit. The inspector becomes a full-width bottom sheet occupying 57% of the work area; closing it restores access to the map. The header can wrap under increased text size. Page-wide scrolling is contained; map, inspector, drawers and worker tray scroll independently. Existing local display, body and utility font stacks are retained, with 15px card titles and 23px inspector headings.

## Graph and progress

The map groups workers by phase and displays declared id/dependsOn edges. Quiet phase headings replace the large Workflow root card and filled phase summary cards. Dashed grouping lines do not imply execution order; dependency arrows remain distinct. JavaScript data dependencies are not inferred. The map shows at most 60 visible workers; every worker remains available through the complete ordered tray and state/phase filters, with hidden records available through More → Show hidden. Phase aggregates include all recorded members, including those outside the preview, and remain in accessible metadata.

Default progress is concise completed/discovered and running-worker counts. Coverage & dependencies exposes queued, failed, unknown and reused counts, the discovery caveat, grouping semantics, hidden/archived records, unknown dependency evidence and omitted prerequisite links. Cards retain full labels, recorded states and prerequisite information in accessible metadata. Prerequisite buttons navigate actual recorded workers, including hidden records without changing their visibility; missing prerequisites stay unavailable. Fit scrolls to the map origin without claiming all nodes fit. Active selects an actually recorded running worker, opens full-tray access when it is outside the preview, discloses hidden-record access through the inspector, or announces that no running worker is recorded.

Engine coverage means completed results divided by discovered workers. A running script may discover more, changing the denominator. No per-worker percentage is invented. Queued, running, completed, failed and unknown states stay explicit; a model's prose cannot overwrite recorded coverage. Engine completion, typed task reports, artifact integrity, acceptance and dashboard health are separate observations. Task reports remain unverified without authoritative acceptance receipts.

A skip link, visible focus, text status labels, accessible disclosure controls and reduced-motion styling support navigation. ## Evidence and activity

Routine polling reads coherent bounded SQLite snapshots. Full worker, script, result, patch and activity reads are deliberate and tied to the observed generation. Cached workers disclose their source generation; prior execution evidence remains inspectable after restart.

The inspector shows title, recorded status, concise task/verification evidence and a bounded text summary before deliberate disclosures. Completed execution output is labelled **Worker result**; a worker report is not coordinator acceptance. Prompt, raw result, workspace/patches, execution metadata/settings, verification/acceptance evidence, tool activity, earlier executions, steering/cancellation and record/prune controls are collapsible. Open disclosures survive unchanged-worker polling and reset on a different worker or generation. Tool filters and paged events show command input/output/status; raw reasoning is excluded. History retains at most 256 records per worker, 4,096 per generation and 16 KiB per record. Discarded history and shortened fields are disclosed. Missing data remains missing; a preview is not presented as full evidence.

Tool failure and worker outcome are distinct: a failed command can precede a completed worker. Native patch evidence may differ from ordinary file-change events; show what was actually observed. Notices can be dismissed locally, keyed by run, generation and stable message identity. Unchanged polls and changing last-good timestamps do not revive dismissed messages. Distinct errors and new generations create fresh notices. Messages retains accessible history, unread/dismissed counts and a 32-message page-local limit with discarded-count disclosure. Dismissal never deletes execution evidence, resolves uncertain receipts, or enables stale/unauthenticated controls.

## Controls

Pause closes admission while active workers finish; stop requests interruption. Receipts distinguish pending, applied and rejected actions from final cleanup. Steering/cancellation targets an exact observed generation, worker position, attempt and active turn.

Resume uses the saved script and original runtime/session. The browser displays the saved script; edited-script resume uses the CLI. Restart shows the eligible suffix and collects an effects-reconciliation note. It repeats the selected worker and all later work, including completed writes. Unknown execution, stale identities or missing cleanup evidence cannot be hidden by retries. No control merges patches or rolls back external effects.

Authenticated mutation conflicts stay visible and require a fresh read. The browser must not automatically resend uncertain mutations. Run status and cleanup proof remain separate until terminal settlement.

## Authentication and lifecycle

The CLI requires originating-session ownership before creating the monitor. The returned loopback URL contains a bearer token in its fragment; the page captures it before API access, removes it from browser history and stores it in tab session storage. Return that complete URL to the owner and keep it out of shared reports.

The server binds only 127.0.0.1 on an ephemeral port, validates Host/Origin and uses a restrictive content security policy. APIs require authentication; static assets expose no run data. Each dashboard invocation creates an independent view, not another model run. There is no default monitor idle expiry; manual Close does not stop the runner. A new current presentation may inspect older retained runs, but every read/control still verifies their original runtime ownership. See [session delivery](session-delivery.md) for visibility, reviewed retirement and lost-response receipt contracts.
