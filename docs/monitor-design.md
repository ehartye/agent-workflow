# Workflow monitor

The session monitor presents a selected persisted run in the owner-selected Map + inspector layout. The approximately 44px blue light-mode run bar shows the actual run title and execution status, Messages, Workers, Pause and the compact ellipsis/down-chevron Run menu. The menu preserves `more-toggle` and exposes a nonmodal dialog with Browse, Run controls and Workspace & evidence groups. It contains session navigation settings, current control identity, Stop/Resume, connection evidence, record management, display/update settings, artifacts and Close dashboard. Refresh now remains in the footer. Opening these surfaces does not change execution or remove records. System, Light and Dark remain available with saved preference and keyboard focus returning from settings on Escape.

The map occupies the remaining viewport beside a desktop inspector that defaults to 300px with its own scrolling. The inspector opens initially on recorded evidence, can be closed, and reopens when a worker is selected. The approximately 31px footer opens the full ordered, filtered worker tray. Run menu and Messages are separate drawers over the retained map and inspector. Escape and Close restore the initiating control using its stable identity. Escape closes an open run picker before its enclosing menu.

Below 600px, the map is a locally scrollable 382px world of two columns of 164px HTML cards. Workers continue across phase boundaries. The desktop graph is never scaled down to fit. The inspector becomes a full-width bottom sheet occupying 57% of the work area; closing it restores access to the map. The header can wrap under increased text size. Page-wide scrolling is contained; map, inspector, drawers and worker tray scroll independently. Existing local display, body and utility font stacks are retained, with 15px card titles and 23px inspector headings.

## Pane widths and remembered appearance

## Authentication and lifecycle

The CLI requires originating-session ownership before creating the monitor. The returned loopback URL contains a bearer token in its fragment; the page captures it before API access, removes it from browser history and stores it in tab session storage. Return that complete URL to the owner and keep it out of shared reports.
