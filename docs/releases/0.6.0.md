# 0.6.0: declared steps, composition and LAN dashboards

Declare workflow steps before workers start. The map shows planned work, actual worker assignments and incomplete terminal steps; declaration dependencies describe the plan without changing scheduling. Stable step revisions support data refresh without rebuilding the view. Older retained runtimes keep their recorded providers and may report visibility unavailable.

Reusable depth-one child workflows run in separate QuickJS processes under the root controller, with separate child concurrency and one shared worker scheduler, authority ceiling and lifetime accounting. Frozen source identities, verified journal replay and ancestor-aware suffix invalidation preserve actual evidence. Explicit trusted-LAN binding validates an exact local private IPv4 address; loopback remains the default. The authenticated dashboard remains available until manually closed.

All four Workflow skills package their complete local reference closure for genuine native skill reads. Managed backend source admission and completion use bounded acknowledged stdin transport instead of oversized command arguments. Windows Git operations use per-command long-path support without changing project or machine settings. Original failed qualification attempts remain retained.

Artifact editing/export/blind-review refinement is still under development and unavailable in this release. Phone painted-layout and keyboard hardening are owner-deferred; second-device LAN acceptance is unverified. Final package, test, native, installation and publication receipts belong to the [release assets](https://github.com/ehartye/agent-workflow/releases/tag/v0.6.0). This source note is not itself a passing gate. GitHub Actions stays disabled; the owner authorized local release verification.
