# 0.4.4: byte-preserving writer diffs

The candidate fixes a real writer handoff failure: Git can emit non-UTF-8 text hunks, and decoding the entire patch as UTF-8 rejected otherwise complete source output. The patch against captured inputs can succeed while the comparison against the Git base fails on an unchanged legacy-encoded file or line-ending differences.

Capture now retains and hashes exact patch bytes for both comparisons. UTF-8 path and object-identity validation remains strict. A non-UTF-8 text preview reports `previewUnavailable: 'non-utf8'`; the monitor identifies the preserved artifact without calling it an empty or complete text diff. The raw artifact remains replayable with Git.

Original failed captures and runs are not rewritten or recollected. Coordinators must reconcile effects and retained source before an explicitly admitted continuation. No inference, capture, patch or preview budgets are raised.

Regression coverage uses actual Git worktrees, invalid UTF-8 without NUL bytes, both comparisons, byte hashes and applied patches. Monitor coverage verifies the unavailable-preview message and artifact identity. Release/install/native acceptance is recorded separately after it actually passes.
