# Agent Workflow 0.6.4

The recorded 0.6.4 runtime's `status` and `result` commands can inspect an owned run
without `run.sqlite`. A bounded finish receipt, paired with a launch request for the
same run directory and session, preserves the retained failure, explicit zero inference,
admission exit evidence and owned cleanup facts. No receipt, invalid evidence or multiple
receipts produce an unavailable report with unknown facts rather than success or a retry.

Existing databases keep the existing read path, including corruption errors. Missing-database
inspection creates no database, changes no retained files and starts no process or admission.
CLI inspection success is not workflow success. The report does not authorize cleanup.

The regression was written first and failed through the public command entrypoint with
ENOENT for `run.sqlite`. It covers ownership-only directories, retained buffered-command
failure with supplied `0xC0000142` exit evidence, CAPABILITY_SOURCES startup cleanup,
missing/mismatched launch evidence, malformed JSON/UTF-8, oversize and contradictory
diagnostics, ambiguous receipts, and an existing corrupt database. Runtime routing is
supplied by a test fixture; the existing managed-entry tests independently exercise actual
verified runtime/session routing. No live admission failure or new model inference is claimed.

Independent review identified nested diagnostic shape and malformed-byte handling gaps;
both received regressions and fixes. Final review found no remaining blockers. See the
[API contract](../api.md#missing-run-database). Final qualification, canonical/tag/archive
identities and publication evidence belong to the release receipt.

Earlier runs still use their original immutable runtime and Node requirements. This change
does not retrofit older runtimes or alter dashboard, list, watch, lifecycle or control reads.
Information never retained remains unknown. Repository Actions is disabled; preserve that
setting and use the established local verification plus canonical/tag/archive verification
route. Do not present absent hosted checks as passing CI.
