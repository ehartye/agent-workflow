## Decisions already binding implementation

1. Retain 512 MiB included payload and each diff, 20,000 included files, 32 MiB metadata/previews, 100,000 excluded entries and 16 MiB excluded inventory. Public preflight shares read-only enumeration/admission with capture; it never calls the mutating `captureInputs` operation.
2. Delivery acceptance is read-only assembly over authentic saved producers, reviewed captures, immutable coordinator checkpoints and fresh integrated checks. A result hash or worker Boolean is not acceptance authority.
3. Jobs are command-only, run-bound durable owners using the existing signed Windows job host around App Server. Directly wrapping a command in the host loses stderr and its exit status; use `command/exec`, output deltas and terminate. Never add an unsigned helper, signing operation or PID-only adoption.
4. Plan preview uses inert Acorn traversal after `parseScript`. Unknown dynamic topology remains unknown. Usage aggregation deduplicates cumulative thread totals across replay/attempt lineage; it is not a native spending cap.
5. Deadline UI extends existing session/run/runtime/generation/attempt/turn/revision controls. Completed-message storage has independent count/byte bounds without changing raw activity sequence, counts, paging or eviction.
6. Recipes preserve criterion/source/null/skeptic coverage and forward genuinely selected skills into actual agent options. The coordinator alone accepts delivery.
7. Release-protection tooling defaults to offline dry-run; tests use local fixture transports. SSH/browser docs do not execute remote login, firewall changes, live settings writes or browser takeover.
8. New job commands take the saved run ID first. This reuses `parseCommand(...).runCommand` and `resolveRun` routing without changes to unowned `bin/launch-v2.mjs` or runtime metadata formats. Old retained runtimes reject unsupported new commands honestly.

## Single-run delivery boundary

This pipeline deliberately adapts the usual separate deliver/verify runs to one owner-authorized run. Explicit external coordinator checkpoints gate fresh verifier calls over an independently frozen integrated checkout. Dependencies order calls and carry reports; they never transfer predecessor edits. The coordinator reviews exact producer/capture/drain identities, integrates verified bytes, freezes a complete content manifest and publishes an immutable external checkpoint. Each verifier checks that manifest before and after its checks. Cached results cannot satisfy fresh acceptance. This adaptation does not claim that the standard bundled decomposition recipe authenticates receipts or implements an integration broker.

The coordinator policy is 30 primary tasks and at most 40 starts including all corrections/appends, at most two explicit correction waves, and `maxAttempts:1` per worker. It is not an engine CLI lifetime cap. Default worker/run wall budgets remain unbounded with a named orchestrator/observer and manual control. Source/control/integration paths remain separately owned. No worker delegates or launches another Workflow runtime.

## Shared identity contract

`RunRefV1 = {dataInstanceId,runId,runtimeId}`. `ProducerRefV1 = {run:RunRefV1,generation,position,attempt}`. Generation is a positive safe integer, position is 0..999 and attempt is the saved cumulative counter (zero remains possible before dispatch). Translate session-local evidence attempt numbers with `attemptOffset`; resolve `reusedFrom` and `priorExecutions` from saved records. Never infer a producer from a label, array index, copied JSON or prompt claims.

All new JSON APIs reject unknown keys, unsafe/nonregular/link paths, invalid UTF-8, oversize inputs and inconsistent identity. Error projections contain bounded trusted categories, not arbitrary stderr, shell bodies, credentials or raw filesystem errors. Unknown/cancelled effects remain unknown until separately reconciled; clean drain alone never permits repetition.

## Normative common record rules

New records use `schemaVersion:1` (existing schema fields keep their current spelling). IDs are portable bounded strings, UUIDs where request identity is required; SHA-256 is lowercase 64-hex; bytes/counts/offsets are nonnegative safe integers. Canonical hashing sorts object keys recursively, preserves array order and hashes UTF-8 JSON. No coercion, accessors, prototypes, additional fields or regex-schema extensions. Limits below are v1 limits, tested at boundary and one over. A JSON source file is opened once, fstat-checked regular, read limit+1 with fatal UTF-8, and link/ancestor checked. Identity is rechecked before action when pathname resolution could change. Serialized response limit is 1 MiB; bulk output is a retained file or bounded page. Tokens and private environment values never enter public metadata.

### Exact shared snapshot and check contracts — revision R1

This revision resolves initial review P1/P2 contract gaps before implementation. It is normative for jobs, acceptance and interfaces. The machine manifest contains the same field lists and deterministic vectors. No producer, test or native acceptance is claimed by these examples.

`FrozenSnapshotV1 = {schemaVersion:1,root,canonicalRoot,rootIdentity,baseCommit,files,exclusions,dependencies,contentSha256,manifestSha256}`. No additional fields. root is the admitted absolute spelling; canonicalRoot is its verified realpath; rootIdentity is `{dev,ino}` with decimal-string filesystem device/inode identities from bigint stat (1..40 digits). An unavailable stable identity blocks qualification. baseCommit is the exact40/64-hex base. files is a sorted complete array of `{path,sha256,bytes,mode}`, with literal relative forward-slash paths, modes100644/100755, no links or case-colliding paths. Paths sort by JavaScript default UTF-16 string order, never locale order. Tracked/untracked implementation, package/lock/plugin/recipe/test/HTML/CSS inputs are included. Count<=20000, payload<=536870912 bytes and serialized snapshot<=1048576 bytes; overflow is blocked, not truncated.

exclusions is exactly `{entries,sha256}`; entries are sorted `{path,kind,bytes,mtimeMs,mode}`, kind file/directory, file bytes a safe nonnegative integer, directory bytes null, mtimeMs finite nonnegative or null when unavailable, mode a nonnegative safe integer or null. Excluded links are refused. Its sha256 is H(C(entries)). Administrative .git and prepared dependency payloads are explicit exclusions, never silently omitted. Every excluded validation dependency is also named in dependencies. Entries<=100000 and inventory<=16777216 bytes, additionally bounded by the snapshot serialization limit. Excluded logs stay external; changing excluded metadata invalidates the recorded snapshot.

dependencies is a sorted array of `{id,kind,path,sha256,bytes}`, unique bounded id<=200, kind file/tree, absolute admitted canonical path, lowercase SHA256 and safe aggregate bytes. It identifies Node/executables, exact retained runtime/dependencies and prepared dependency tree/package-lock as applicable to each check. File hashes cover raw bytes. Tree hashes cover C(sorted complete relative `{path,sha256,bytes,mode}` inventory); reject links and bound each tree by the same20000-file/512MiB limits. Hash actual dependency bytes, not a version string, mtime or lockfile alone. A dependency's absolute location belongs to manifest identity; byte equality between validation copies uses id/kind/sha256/bytes.

C is canonical UTF-8 JSON with recursively sorted object keys, unchanged array order and no whitespace/newline; H is SHA256. contentSha256 is H(C(`{baseCommit,files,dependencies:dependencies.map(({id,kind,sha256,bytes})=>({id,kind,sha256,bytes}))}`)). manifestSha256 is H(C(the entire snapshot with only manifestSha256 omitted)); it includes contentSha256, both root spellings/identity, exclusions and full dependency paths. A supplied hash must match recomputation. verifyIntegrationSnapshot returns the full validated recomputed FrozenSnapshotV1; it never fills missing evidence with guessed hashes. Before/after equality is exact manifest/dependency equality for one root, with the validation-copy mapping below the only explicitly admitted different-root case.

`CheckRequirementV1 = {id,executable,executableSha256,argv,cwd,environmentHash,required,scope}`. argv ALWAYS EXCLUDES executable.
