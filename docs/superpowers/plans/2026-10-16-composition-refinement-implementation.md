Qualify the implemented candidate using a newly installed, independently frozen runtime whose native run refs are linked back to this pipeline.

Owner direction includes both features and source/marketplace shipment, with **Actions off until the owner changes that instruction**. Coordinator alone owns orchestration, reviewed integration, publication and exact protection restoration. Implementation writers do not launch actual workflows or delegate. This plan's doc writer performed bounded source/native skill reads and four owned Markdown artifact writes only, with no tests, installs, jobs, Git metadata changes, network or publication.

Bulk manifests never expand an answer allowance.

## Work shape and dependency graph

Choose one coordinator root with isolated writers and reviewed handoffs. Root iteration/helper emits depth-1 producer/reviewer siblings. Keep native-worker permits unchanged; a separate child-evaluator lifetime pool is sized to root concurrency, with **all** live/suspended child processes counted until settlement. Waiting children hold no native-worker permits. Root is outside the child pool, depth 1 cannot recurse, and concurrency 1 must be deadlock-free. Retain QuickJS pump/CPU/heap/idle and JSON-only broker; no yielded/resume-ack protocol or combined child/native permit queue. Global worker/request/start/attempt/broker limits stay root-owned. Manual lifetime with no worker wall deadline is deliberate, with explicit existing startup/command/drain/run limits and controls.

Enumerated dependencies: phase 0 contract review → phase 1 readiness/fixtures → phase 2 core source/schema foundation → phase 3 artifact providers and phase 4 dashboard/docs in their own worktrees → phase 5 reviewed integration → phase 6 integrated failures/independent reviews → phase 7 new-runtime native/browser qualification → phase 8 final freeze/full package gates → phase 9 source/marketplace publication and protection restoration. Artifact/UI authors can write against phase-0 exact contracts independently; dependent combined tests wait for reviewed provider integration. Phase labels are presentation only; the coordinator records real dependency IDs and barriers.

Alternatives were assessed in each spec with Time/Risk/Complexity/Best practice/Maintainability. This plan does not reopen the accepted architecture or the coordinator's separate child lifetime pool refinement. The only additional design scope is the explicitly requested bounded LAN launch below.

### 4.6. Declared steps before assignment (objective S)

Current `engine/monitor/experience.mjs` derives phases/graph content from discovered workers only. `engine/plan-preview.mjs` is an inert preview, not a declared dispatch plan. Add one optional bounded literal `meta.steps` array (omission means `[]`) through core's existing parseScript/preview/controller owners. It is a plan/display catalog, not executable scheduling or acceptance machinery.

Exact minimal declaration, with only phase and worker optional:

```text
StepDeclaration = {
  id:Id,label:Text(500),dependsOn:Id[0..255],
  phase?:Text(500),worker?:{id:Id}
}
StepCatalog = StepDeclaration[0..256]
StepScope = {kind:"root"}|{kind:"child",invocation:ChildRef}
StepRef = {run:RunRef,generation:positive integer,scope:StepScope,stepId:Id}
StepCatalogV1 = {
  schemaVersion:1,run:RunRef,generation:positive integer,scope:StepScope,
  sourceId:Sha,steps:StepCatalog,catalogHash:Sha
}
```

Use composition Id/Text/strict-JSON/path-safe ID rules; IDs/dependency IDs/worker IDs are literal, case-sensitive matches with case aliases rejected. Catalog ≤256 entries and ≤262,144 compact UTF-8 bytes, also within current 1 MiB script and literal-depth limit. Labels may repeat and never identify nodes. Reject extra keys, null optional values, expressions/accessors, duplicate IDs/edges, case aliases, empty/malformed names, self-edge, unknown dependency, cycle, duplicate declared worker binding or out-of-scope binding before dispatch. `dependsOn` resolves only within that exact source/evaluation scope, including forward references; use deterministic topological validation/layout, retaining catalog order as tie-breaker. An optional `worker:{id}` names an exact **local** agent options.id, not an already-created WorkerRef. It asserts no future worker existence. Child step IDs/worker IDs belong to that child's actual invocation, never a flat root namespace. Root catalog is durable before root evaluation/first worker; each child catalog becomes visible at its admitted invocation intent before child process/worker dispatch.
