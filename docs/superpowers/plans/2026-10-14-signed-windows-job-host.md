# Signed Windows process helper

PlanetForge roadmap scouting exposed a Windows distribution defect in Agent Workflow 0.3.1. Code Integrity events 3077 and 3033 at 2026-10-14 10:11:37 EDT identify the original launch's temporary `workflow-job-host.exe`; the same events at 10:20:41 identify the fresh command-only diagnostic helper. Both executables are `NotSigned`. This establishes the blocked component on this machine, independently of the generic historical completion error. It does not diagnose the other computer's Node loader issue.

The current helper starts the native server suspended, assigns it to a non-breakaway Windows job before execution, retains handles, terminates the job on host closure, and acknowledges an empty job separately from protocol completion. Preserve that boundary. Do not replace it with process-name killing, an unowned launch, a different sandbox, self-signed local trust, or instructions to disable Smart App Control.

## Delivery contract

1. Build the reviewed C# helper once for the package. Record the exact source digest, compiler/toolchain identity, architecture and build inputs; sign the resulting executable through the approved Microsoft Artifact Signing Public Trust profile. The local candidate is signed. Repeatable Windows release-lane signing and final publication remain separate delivery gates; no exported private key or local trust override is required.
2. Package the signed executable and a bounded release manifest binding source, executable digest, architecture and expected publisher identity. Include the binary and manifest in source/runtime/dependency identity verification. A hash proves bytes; it does not authenticate the publisher or establish source equivalence by itself.
3. Production setup hashes and copies the package into the managed runtime, including the helper, manifest and trust policy. Backend startup then verifies regular unlinked file shape, source/binary hashes, x64 architecture, valid Windows Authenticode signature, approved profile-specific EKU and timestamp before using the packaged helper. Missing, altered, unsigned, wrong-profile or untrusted helpers fail before native App Server startup, without compiling another executable or falling back. The profile EKU remains stable across daily leaf-certificate renewal; leaf thumbprints are not the trust policy.
4. Keep development compilation an explicit development/release operation. Do not silently compile an unsigned helper during production doctor, workflow dispatch, cleanup or worker startup.
5. Extend the existing Windows-job invariant owner with failing tests for packaged identity/trust rejection, then retain its real suspended-assignment, normal closure, cancellation, host-death and detached-descendant checks against the signed artifact. Test in Smart App Control enforcement, requiring no new block events for the helper and positive owned-job drain. CI passing without enforcement cannot supply this acceptance.
6. Run a fresh command-only doctor and detached launch through the clean published package on the affected machine. Preserve the original failed run and its missing historical cleanup. Verify genuine worker skill calls and required Meshes readiness before allowing tool-dependent modeling. GLB/rig/browser/Blender operations and artifact quality remain separate acceptance checks.
