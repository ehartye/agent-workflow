## Bounded LAN addition review

Owner explicitly added dashboard LAN ability/guidance. Plan4.3..4.5 is the complete bounded design for later implementation, not shipped behavior. Proposed `dashboard --lan-bind <local-private-IPv4>` is dashboard presentation only, leaves loopback/port0 default and worker authority unchanged. It validates canonical RFC1918 IPv4 against actual local non-internal interface before fork, revalidates in child and refuses wildcard/public/nonlocal/malformed/ambiguous choices without fallback. Returned URL preserves actual selected address/ephemeral port, original run path and auth fragment. Receipt/health/ready/commit/started retain exact network and service identity; any reuse cannot confuse LAN with loopback.

Host/Origin remain exact advertised values, no wildcard CORS, auth/token/runtime/session/manual-Close downgrade. Existing core owns arguments/CLI/server/launcher; UI/docs consume its frozen seam. Tests are assigned to actual public argument/entry, real HTTP and launcher owners: invalid-before-fork, unauth401/auth200/foreign-origin403, path/address/port, network identity mismatch, loopback regression and explicit shutdown. An unavailable local private interface is a test prerequisite gap, never a green skipped LAN qualification. Optional Windows firewall guidance is exact Private profile + LocalSubnet + verified Node program + chosen address/actual port + owned rule name, only after reachability necessity and separate explicit authorization. No firewall was read/changed here. Local-interface HTTP evidence cannot stand in for second-device painted-browser acceptance; the latter remains unrun and separately scoped.

## Concrete remaining implementation risks and release blockers

1. **Native image observation may be insufficient in the pinned native version.** Existing projection deliberately treats media/unsupported wrappers as unknown. Core must inspect first-party pinned schema/source and prove real packet-image call/output linkage with positive/foreign-image negatives. If unavailable, keep visual acceptance unverified and block visual-pass shipment claims; never invent an endpoint.
2. **Journal migration versus retained runtime integrity.** New invocation records, source revisions, derived inputs and controls must be versioned under a new runtime. Old saved runs keep their original provider/API. Missing/corrupt data or catalog drift must refuse before generation mutation; no migration by editing headers.
3. **Two-pool lifecycle races.** Fork failure, waiting children, queued cancellation, child exit before parent reply and unknown native drain can leak permits or admit too much. Actual spawn/exit plus SQLite tests must prove child≤C and native≤C independently and concurrency1 completion. A heap bound per child is not an aggregate process bound by itself.
4. **Filesystem time-of-check/race boundaries.** Link aliases, parent preimages, deletions, unowned generated files and policy exclusions can invalidate handoffs. Verify before/after materialization, retain partial artifacts, and preserve same-user filesystem limitations; inherited parent access is not an OS isolation claim.
5. **Exact schema expansion and cost.** Deep role schemas/64 criteria/long paths can hit literal depth, compiled cost/result or 1MiB page/start limits. Admission must calculate actual envelopes and minimum complete answer size; split explicit roles rather than inflate limits/truncate coverage. Current design is specified, not compiled/qualified.
6. **Atomic publication and lost responses.** Filesystem publication and SQL commit are separate. Unreferenced staged artifacts cannot authorize effects; durable intent without confirmed outcome is unresolved. Request-id replay, source suffix invalidation, round completion and pending control races need crash tests, not mocked success.
7. **Semantic and independence guarantees remain scoped.** Packet/context blinding cannot prevent deliberate filesystem searching under parent authority. Native fresh threads, complete all-required review and immutable original dissent must be proved; neither identical bytes nor completeness critic can supply absent semantic evidence.
8. **Review reuse/progress are intentionally conservative.** Same-byte new provenance cannot reuse exact-candidate reviews. Different failed output may never trigger the initial dry rule; explicit maxima/manual controls/root backstops remain visible. No general convergence guarantee or model-quality advantage is promised.
9. **Provider integration may drift between writers.** Core alone integrates shared controller/workspace/CLI/native/LAN/steps seams. Review exact exports/schema/source refs and wait for actual combined source before dependent tests; do not copy foreign providers or fabricate check receipts.
10. **LAN address/lifecycle and browser scope.** Interface changes, forged startup receipts, accidental loopback reuse and lost commit replies need fail-closed tests. Optional firewall necessity/authorization and actual second-device painting remain unverified. HTTP LAN is not public hosting or TLS deployment.
11. **Declared-step coverage can mislead.** A finite catalog is not a closed executable worklist. Preserve dynamic unknown coverage, unassigned terminal steps, actual/source WorkerRefs and no overall completion percentage from plan counts. Plan dependencies cannot be advertised as scheduler gates.
12. **Source/package/release evidence can become stale.** Final F/V, actual installed candidate, full test/check/smoke/clean install/audit and native related runs must match exact final source. Actions remain off; source/marketplace publication and every original protection leaf require actual coordinator evidence and exact restoration. No current full host/Claude/shared-budget/Linux/macOS/second-device parity claim.

These are concrete implementation/verification gates, not unresolved hidden API or authorization choices. Missing native reference access, all unrun tests/native/render/browser/LAN/release gates and external wiki follow-through remain explicit.
